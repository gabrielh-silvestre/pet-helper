# Traces are OpenTelemetry spans from OpenLLMetry, written to a local file and to LangSmith when a key is set

The own JSONL trace (one hand-made event per line, our sink, our ids) was the biggest piece of custom code that a market tool covers. The unit `market-tools-adoption` replaces it with OpenTelemetry spans: the OpenLLMetry instrumentation for LangChain (`opentelemetry-instrumentation-langchain`, pinned `>=0.62.4,<0.63`) creates the model and tool spans, and a thin layer of our own code writes what the library does not know. Four things are not negotiable and shaped the choice: a PII-free trace (CPF, e-mail and phone masked before anything leaves the machine, the local file included), time to first token (TTFT) and the domain events (escalation, refused second CPF, `NOT_FOUND`) in the trace, requirement 6 of the challenge (a trace that explains why the bot answered), and an evaluator without an account, so the destination is a local file unless `LANGSMITH_API_KEY` is set.

This reverses two rejections of 2026-10-29 in `docs/architecture.md`: "OpenTelemetry with OpenInference" (section 2) and "LangSmith" (section 5). Both stay rejected as they were argued then (an account and cloud storage for every evaluator; roughly 15 spans per turn with no TTFT), but neither argument survives the new shape: LangSmith is now an optional destination chosen by an environment variable, and the span count is accepted.

## Considered Options

- **A1, OpenLLMetry creates the spans** (chosen by the owner): the library creates the model and tool spans with `gen_ai.usage.*` tokens. Our callback writes onto the span of each run, through the `run_id`: TTFT (`gen_ai.server.time_to_first_token`), cost, fallback and streaming flags, cache tokens, the brake-error usage and status, and the tool arguments, result and status. The root span of the turn is ours and carries the domain events as span events. A single `MaskingSpanExporter` sits in front of every exporter (file and LangSmith OTLP) and is the only place that masks.
- **A2, OpenInference instrumentation**: rejected. It uses its own `llm.*` convention, does not measure TTFT and knows no domain events.
- **A3, `langsmith[otel]`**: rejected. It does not measure TTFT or carry domain events, and it is a second path to the LangSmith that could leak personal data without our mask. The anonymizer of the LangSmith client covers only runs of that client, not the OTLP export nor the file.
- **A4, own callback handler that creates the spans** (the critic's decision, revoked by the owner, kept as the fallback): no dependency on an internal API, full control of the span names and attributes, at the price of keeping the code that A1 deletes. It returns when the H1 contract test cannot pin TTFT or cost to the span of its call, when the span loses `gen_ai.usage.*`, or when a 0.62.x release changes the `spans` map or the `SpanHolder` of the handler.

## Consequences

- Without `LANGSMITH_API_KEY`, spans go to `traces/<date>/spans/<session_id>.jsonl`, one span per line, and the assistant behaves the same. With the key, spans also go to `https://api.smith.langchain.com/otel/v1/traces` (project from `LANGSMITH_PROJECT`, default `pet-helper`), always behind the `MaskingSpanExporter`. The LangSmith tracer itself is disabled with `tracing_context`, because its runs would carry unmasked text.
- The mask keeps the rules of `docs/architecture.md` section 2 (`Guard.mask`, Presidio regex-only, CPF as an HMAC pseudonym). Opaque keys (model name, session id, span kind) are listed by exact name, never by prefix. Truncation to 10,000 characters comes after the mask. `PET_HELPER_TRACE_CONTENT=0` turns free text into its length in the same exporter.
- OpenLLMetry content capture is off (`TRACELOOP_TRACE_CONTENT=false`): the model prompt carries order data outside the `OrderView` allowlist. The panel shows the customer message and the reply on the root span, and the tool arguments and results on the tool span, all masked. The system prompt and the intermediate completions are not in the trace; the owner accepted that loss.
- Shortcut, marked `shortcut:` in the code: the span of a run is read from `handler.spans[run_id].span`, an internal attribute of a 0.x package. A contract test pins it, and the version pin (`<0.63`) limits the exposure.
- Deviation from the plan: `uninstrument()` does not remove the LangChain and LangGraph wrappers in 0.62.4, so a second `instrument()` would keep sending spans to the first provider. `install()` therefore instruments once and forwards every span to the provider of the latest install.
- When the cost brake raises `BudgetExceeded`, LangChain never calls the error callback of that run, so `fail_run` ends the OpenLLMetry span with the error.
- Cost for the brake and the reports still comes from `genai-prices` in process: LangSmith prices exist only in the cloud, and the US$5 cap needs the number before the call returns.
- The old JSONL sink stays active, beside the spans, until the owner step P1b (parity round with LangSmith) passes. Then the readers (`pet-helper metrics`, the round collector, the PII audit) move to the `spans/` files and the sink is deleted. Rounds recorded in the old format are not read by `pet-helper metrics` afterwards (owner decision).
- The dependencies (`opentelemetry-sdk`, `opentelemetry-exporter-otlp-proto-http`, `opentelemetry-instrumentation-langchain`, `langsmith`) are in the base install: without the instrumentation there is no model span.
- The panel checklist of P1b (model and tool spans, tokens, cost, latency, TTFT, domain events, grouping by session, no PII, no duplicate trace) is an owner step and is not recorded here yet.
